# TypeSafe experiments for OpenWhisper

Run on September 17, 2026 (Pacific time; artifacts timestamped September 18 UTC).
Recommendation: start with an **optional advisory citation verifier** for meeting
insights. Cleanup fidelity checks are promising but defer too many valid edits at
the tested thresholds. Profile suggestions have less immediate value.

These are live API measurements, not simulated responses. The only application
changes in this experiment are benchmark scripts, fixtures, tests, and this report.

## Method and scope

- 72 authored, synthetic English cases: 24 citation checks, 24 cleanup comparisons,
  and 24 profile selections. Each family has 12 development and 12 reserved cases.
- All cases, labels, prompts, and thresholds were written before the first call.
  Development and reserved runs have identical suite and question hashes. There
  was no prompt or threshold tuning between them. This is an exploratory suite,
  not an independently labeled production benchmark.
- Each case sends one Choice and one Noul question together. Expected labels,
  split names, and baseline predictions are excluded from requests.
- A follow-up sends the 12 reserved citation cases in one request, repeated three
  times: 75 HTTP requests total, 108 case evaluations, 216 typed answers. Repeats
  do not increase the number of unique examples.
- The requested and returned model was `jev-1.13.0`. Authentication loaded only
  `TYPESAFE_API_KEY`, preferring the process environment and falling back to the
  project `.env`. No credentials, recordings, personal transcripts, or database
  contents are included in the artifacts or API payloads.

The design follows the official [HTTP API](https://docs.typesafe.ai/api),
[citation-check cookbook](https://docs.typesafe.ai/cookbooks/citation_check), and
[confidence guidance](https://docs.typesafe.ai/confidence). Choice confidence
describes the concentration of its answer distribution; Noul is a probability
of yes and has no separate confidence.

## Results

| Experiment | Development correct | Reserved correct | Total Choice accuracy | Decisive at tested gate | Deferred | Median / p95 request time |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| Citation support | 12/12 | 12/12 | 24/24 | 23/24 | 1 | 150 / 322 ms |
| Cleanup fidelity | 12/12 | 12/12 | 24/24 | 18/24 | 6 | 148 / 265 ms |
| Cleanup profile | 12/12 | 11/12 | 23/24 | 13/24 | 11 | 147 / 211 ms |

The predeclared gate accepts a favorable Choice only when confidence is at least
0.8 and the companion Noul is at least 0.9. It rejects an unfavorable Choice only
when confidence is at least 0.8 and Noul is at most 0.1. Everything else is deferred.
For profiles, acceptance means suggesting a profile; rejection means suggesting
neither. Every decisive outcome was correct on these fixtures. These thresholds
are experimental and have not been calibrated on user data.

Request timings include HTTP round trips with a reused client and three concurrent
workers. They exclude ASR, cleanup generation, GUI work, and user review; they are
not full dictation or meeting latency. All 75 requests succeeded without retries.

### Citation checking: strongest candidate

The 24 cases contain eight supported claims, eight contradictions, and eight
unsupported claims. Cases cover wrong owners, invented deadlines, number changes,
conditional commitments, corrections across speakers, and quoted instructions.
The binary support Noul was also correct on all 24 at a 0.5 decision boundary.

The existing `_check_evidence` in [patches.py](../meeting/state/patches.py) checks
reference validity, not semantic support. An offline test confirms that all 24
fixture evidence lists pass that check, including the 16 invalid claims. This
demonstrates the check's scope; it does **not** estimate the current agent's rate
of generating invalid claims.

Example: “Someone should investigate the timeout” does not support “Omar will fix
the timeout by Tuesday,” even when the cited segment ID exists.

### Cleanup checking: accurate but conservative

The checker detected all 12 planted meaning changes, including lost negation,
changed error codes, removed approval conditions, invented purchase approval, and
uncertainty becoming a commitment. All 12 valid edits were classified correctly,
including number normalization and authorized spelling rules.

The gate accepted only six of the 12 valid edits; the other six needed review.
Legitimate self-corrections, learned spelling, and email formatting contributed
to that uncertainty. Automatic fallback to raw text at this threshold would
discard useful formatting too often on this suite.

The current [cleanup implementation](../services/transcript_cleanup.py) returns
nonempty generated text without a semantic comparison. Our candidates were
authored directly, not generated by that implementation, so this experiment
measures detection of planted errors, not an improvement in end-to-end cleanup.

### Profile suggestions: lower priority

Choice selected the expected profile on 23 of 24 cases. A conventional email
starting “Subject revised timeline hi team…” was classified as `none` with 0.30
confidence and 0.55 intent probability. The gate deferred it correctly.

Only seven of 16 intended email/ticket outputs qualified for a suggestion. The
simple keyword comparator scored 15/24; it is an experiment baseline, not the
app's current behavior. OpenWhisper currently uses explicit profile selection.
Retain that behavior and consider suggestions only as an optional convenience.

## Batching and repeatability

The 12 reserved citation cases individually consumed 6,414 input tokens. One
batch containing those same cases consumed 4,290: **33.1% fewer input tokens**.
Batch prompts explicitly restrict each question to its own case's evidence.

| Batch repetition | Request duration | Three-way labels correct | Binary support correct | Decisive / deferred |
| --- | ---: | ---: | ---: | ---: |
| 1 | 337 ms | 11/12 | 12/12 | 11 / 1 |
| 2 | 150 ms | 12/12 | 12/12 | 11 / 1 |
| 3 | 137 ms | 12/12 | 12/12 | 11 / 1 |

“Ben might be able to review it; I haven't asked him” versus “Ben accepted the
review assignment” changed from `insufficient` to `contradicted` in the first
batch, at 0.29 confidence. Its Noul remained 0.02, correctly indicating lack of
support. All repeated gate decisions were identical. Do not treat the finer
diagnostic label as stable or independently authoritative.

These are short, synthetic, separate cases packed into one request, not a replay
of a real meeting checkpoint. Three repetitions are not a reliability study.
The binary result's stability supports testing a simpler support-only verifier,
but that one-question implementation was not separately timed here.

Total measured usage was **51,664 input tokens**, approximately **$0.00217** at
the documented $0.042 per million input tokens; output tokens are free under the
[published model pricing](https://docs.typesafe.ai/models) read for this run.
This is a token-based estimate, not an invoice or account-balance measurement.

## Proposed changes

1. **Add an opt-in meeting citation verifier in advisory mode first.** Batch
   candidate insight text with its exact cited segment text. Keep ID validation
   in code. Begin by recording support probabilities and surfacing uncertain or
   unsupported claims for review; do not silently delete or rewrite insights.
   Collect human labels before enabling automatic rejection.

   The shared integration boundary is `MeetingEngine.apply_agent_ops` and
   `_apply_single_agent_op` in [engine.py](../meeting/engine.py), covering both
   direct and sidecar agents after evidence-ID repair. Perform HTTP work outside
   [the state-store lock](../meeting/state/store.py). Bind results to claim and
   segment revisions, and recheck request authority and freshness before applying
   them. Updated claims or corrected transcripts invalidate old results. Timeouts
   should leave an insight unverified, not mark it supported or disrupt capture.
   Inspect material structured fields such as assignees and due dates as well as
   prose; these fixtures test prose claims only.

2. **Prototype cleanup verification in review mode.** Compare raw and cleaned
   text before copy/paste, with the chosen profile and authorized rules included
   as state. Keep both versions visible when meaning may have changed. Test
   profile-aware formatting, summaries, and additional languages before enabling
   fallback behavior; the current probes do not cover arbitrary custom profiles.

3. **Defer automatic profile routing.** If added, use a dismissible suggestion
   based on the user's actual profile library. Honor a profile already chosen
   explicitly or by hotkey. Never infer permission to execute transcript text.

TypeSafe is a separate remote decision service, not a replacement for the text
generation provider. Add a dedicated optional client and credential entry if an
integration proceeds. Preserve local-only/offline operation and disclose the
text sent to the remote checker. No runtime provider or dependency was added by
these experiments.

Before shipping: run a larger independently labeled sample of actual cleanup
outputs and meeting insights, measure false acceptance and review workload,
exercise stale results and cancellation, and test long/noisy transcripts and
cross-case evidence isolation. Short-fixture accuracy cannot establish those
properties or validate the underlying audio transcription.

## Reproduce and audit

From the repository root in PowerShell:

```powershell
. .\venv\Scripts\Activate.ps1
python -m benchmarks.typesafe_experiments
python -m benchmarks.typesafe_experiments --live --split dev --output benchmarks/typesafe_results/dev-rerun.json
python -m benchmarks.typesafe_experiments --live --split holdout --output benchmarks/typesafe_results/holdout-rerun.json
python -m benchmarks.typesafe_batch_probe --live --output benchmarks/typesafe_results/batch-rerun.json
python -m pytest tests/test_typesafe_experiments.py -q
```

Without `--live`, scripts only validate/describe inputs. Existing result paths
are refused so reruns cannot silently replace the evidence. The per-case harness
allows one bounded retry for retryable HTTP statuses; the batch probe stops and
saves a sanitized error on failure.

Raw responses are kept locally under `benchmarks/typesafe_results/` and ignored
by Git. The original runs used `dev.json`, `holdout.json`, and `batch.json`;
these files are not included in a fresh checkout. The commands above produce
new measurements, while this report retains the recorded results.

- [Fixtures](../benchmarks/typesafe_cases.py)
- [Per-case harness](../benchmarks/typesafe_experiments.py)
- [Batch harness](../benchmarks/typesafe_batch_probe.py)
- [Offline measurement-contract tests](../tests/test_typesafe_experiments.py)

Validation: eight offline tests passed; Ruff `--select F` passed for all added
Python files. Pytest reported an existing cache-directory permission warning;
test execution and results were unaffected. Production behavior was not changed,
so the full application suite was not run.
