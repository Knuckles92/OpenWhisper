# Prominent Insights Redesign — Live Meeting Dashboard

Redesign the live dashboard so the 3 most important insights get a prominent, always-evolving "spotlight" row under the topic hero, and the right rail becomes a scannable "greater context" area. **Webui-only change** — no Python/backend/schema changes. History view untouched.

## 1. Selection helper — `webui/src/state.ts`
- Move `CAPTURE_TAGS` (singular labels: "Key point", "Decision"…) out of `CardsPane.tsx` into `state.ts` next to the existing `CARD_LABELS`, exported for sharing.
- Add exported `selectSpotlightItems(cards, limit = 3): { key: CardKey; item: CardItem }[]`:
  - Flatten all six card lists, exclude `status === 'removed'`.
  - Rank: `pinned` first → human-touched (`edited`/`confirmed`) → `updated_at` desc (same ISO-string compare as `sortedCardItems`).
  - Greedy pick at most one item per card category; if fewer than 3 picks after the first pass, a second pass fills remaining slots allowing category repeats.

## 2. New component — `webui/src/components/SpotlightRow.tsx`
Props: `cards`, `status`, `cloudEnabled`, `intelligenceOnline`, `onSendOp`, `onEvidenceClick`. Renders up to 3 `SpotlightCard`s plus ghost placeholders for empty slots.

Each **SpotlightCard**:
- Category tag (reuse `capture-tag` styling) + `· proposed` suffix for agent items, pinned marker for pinned items.
- Large text (~1.05–1.1rem, line-clamped to 4 lines), double-click to edit via inline textarea (same pattern as `CardItemRow`), using `ops.updateItem`.
- Evidence chips (reuse `EvidenceChip`).
- Meta line: relative updated time ("just now", "2m ago", "1h 14m ago") via a small local helper, computed on render.
- Actions: Pin/Unpin, Confirm (when not confirmed), Remove. Undo stays in the rail only, keeping the card face clean.

**Ghost placeholders** for empty slots reuse TopicHero's context-aware copy (cloud off → "Enable cloud insights to generate live insights."; ending → "Wrapping up insights…"; intelligence offline → "Cloud intelligence is offline"; default "Listening for insights…").

## 3. Wire in — `webui/src/App.tsx`
Render `<SpotlightRow>` between `<MeetingOverview>` and the ActivityPane, passing `ui.state.cards`, status flags, `sendOp`, and `handleEvidenceClick`.

## 4. Rail becomes the context area — `webui/src/components/CardsPane.tsx`
- Import `CAPTURE_TAGS` from `state.ts` (no duplication).
- Add a per-section heading with count above each group ("KEY POINTS · 3") using the existing-but-currently-unused `.card-section-title` CSS class; the per-item rows, tags, status suffix, and all actions stay as the full record.
- Keep the capture composer and QuestionInbox as-is.

## 5. Styling — `webui/src/styles.css`
- `.spotlight-row`: `grid-template-columns: repeat(3, 1fr)`, gap 16px; collapse to 1 column ≤900px (matches `.stage` breakpoint).
- `.spotlight-card`: elevated panel look consistent with the sage theme (paper mix background, hairline border, ~18px radius), larger type, `@keyframes spotlight-in` entry animation (same rise/fade pattern as `hero-rise`), pinned variant with leaf accent, proposed variant keeps the suffix treatment.
- `.spotlight-ghost`: dashed border, muted centered placeholder text.
- `.card-section-count` styling for the new rail headings; modest font-size bump for `.card-item-text` so the rail reads less cramped.

## 6. Static design mock — `webui/mocks/11-spotlight-row.html` (+ entry in `mocks/index.html`)
A standalone hardcoded HTML mock of the new hero + spotlight row + rail, matching the repo's existing mock-gallery convention, so the design can be previewed/tweaked without a running meeting server.

## 7. Build & verify
- `npm run typecheck` and `npm run build` in `webui/` (refreshes `webui/dist`, which is the committed artifact the Python server serves — rebuilt but not committed unless you ask).
- Visual sanity check of the mock in a browser with a screenshot before/after implementing the React version.
- No Python tests affected; `pytest` not needed for this change.
